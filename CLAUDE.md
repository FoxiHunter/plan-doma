# План дома и участка

Я планирую одноэтажный дом для своей семьи и делаю для этого офлайн-конструктор. Это одна HTML-страница с 2D-редактором плана и 3D-видом на three.js. Готовый файл открывается двойным кликом в браузере, работает без интернета и сам сохраняет план в localStorage. Та же страница в варианте для сайта лежит на GitHub Pages и стартует с пустого участка и мастера.

Факты о доме, участке, нормах и бюджете лежат в `docs/project-memory.md`. Этот файл есть только у меня на диске, в публичный репозиторий он не уходит. Читай его, когда задача касается планировки, норм или денег. Как проверять код, описано в `docs/testing.md`.

## Как со мной работать

- Отвечай по-русски. Первым символом первого сообщения сессии ставь ✅.
- Комментариев и докстрингов в коде нет никогда, объяснения пиши в сообщении рядом с кодом.
- Один пробел до и после `=`, `+=`, `===` и логических операторов. Присваивания в колонку не выравнивай.
- Не добавляй фичи, о которых я не просил. Идею пиши отдельной строкой после работы.
- Дебаг начинай с гипотезы и способа её проверить, потом фикс. Не переписывай наугад.
- Не выдумывай методы и аргументы. API three.js сверяй с `src/vendor/three.min.js`, это r128.
- В текстах не используй длинное тире и маркер «•», для списков бери «-».
- Не пиши «работает», если не прогнал проверки из раздела «Команды».
- Спрашивай перед удалением файлов и перед любыми действиями вне папки проекта.
- Задача на несколько шагов начинается с короткого плана. Большую работу делай по частям и говори, сколько её.

## Команды

- `npm install` ставит jsdom для проверок. Пакеты `gl` и `pngjs` опциональные, они нужны только для `npm run render`. На Node 26 `gl` не собирается, тогда 3D проверяй в браузере.
- `npm run build` собирает из `src/` два файла. `dist/plan-doma.html` это моя локальная версия, в неё попадают мои шаблоны из `src/app/presets.local.js`, если этот файл есть. `site/index.html` это версия для сайта, в ней стоит флаг `window.PLAN_WEB = true`, она стартует с пустого участка и мастера, мои шаблоны и примеры в неё не попадают.
- `npm run check` собирает и гоняет проверку логики в jsdom для обоих файлов. Любая строка FAIL значит поломку.
- `npm run render` собирает и рендерит 3D в `renders/*.png`. На Linux запускай через `xvfb-run -s "-ac -screen 0 1280x1024x24" npm run render`.
- Для проверки в браузере в `.claude/launch.json` есть конфигурация `plan`. Она поднимает `python3 -m http.server 5178`, локальная версия открывается по адресу `http://localhost:5178/dist/plan-doma.html`, версия для сайта по адресу `http://localhost:5178/site/index.html`. У обеих на localhost общий localStorage.
- Для разработки можно открывать `src/index.html` прямо в браузере, сборка для этого не нужна.
- Сайт собирает GitHub Actions из `.github/workflows/pages.yml` при каждом пуше в `main`. Сначала идёт `npm run check`, потом `site/` выкладывается на GitHub Pages.

После любой правки в `src/` запускай `npm run check`. После правок 3D ещё и смотри картинку глазами, через `npm run render` или во встроенном браузере.

## Файлы

`src/index.html` держит разметку и все стили. План и 3D занимают всё окно, поверх них плавают верхняя панель `.top`, инструменты `#rail`, подсказка `#hint`, лента времени `#sunbar` и окно погоды `#wxpop`. Справа карточка свойств `.sidecard`, она сворачивается кнопкой в верхней панели. Цвета интерфейса и плана заданы переменными CSS для светлой и тёмной темы, тема берётся из системы или из `UIP.theme`.

Скрипты подключены тегами `<script src>` в таком порядке, сборка заменяет их вставкой кода.

- `src/vendor/three.min.js` three.js r128 без изменений. Не читай его целиком и не правь, файл весит 600 КБ.
- `src/app/texgen.js` генерация текстур на видеокарте. `TEXDEF` хранит размер плитки в метрах, разрешение и глубину рельефа, `GLSL_K` шейдер каждой текстуры. `texGen` рисует цвет, карту нормалей из высоты и карту шероховатости со швами. `matSwatch` рисует превью материала для панели.
- `src/app/shade.js` общий патч шейдеров `shadePatch`, его получает каждый материал из `mat()`. Общие юниформы `SHU`. Свет неба в докрутке даёт только рассеянный свет без бликов, блики на рельефе сглаживаются по длине нормали из мип-уровня, внутри дома рассеянный свет неба приглушается (`shadeInterior`).
- `src/app/mat3d.js` библиотека материалов `MDEF` с русскими названиями и группами `MGROUPS`, ключи материалов со своим цветом `specKey`, `mat()`, примитивы `B`, `RB`, `Cy`, `Sp`, `Lb`, `Lump` и другие. Мягкие вещи строят `Cushion` (скруглённый брусок с выпуклым верхом и посчитанными нормалями без шва на скруглении) и `Pillow` (подушка, тоньше к краям), точёные ножки `TLeg`. Выпуклость у `Cushion` всегда вверх по локальной оси y, спинки и изголовья кладут её в группу, повёрнутую вокруг x. Мелкие одинаковые детали (штакетины, прутья, дрова) склеивает в один меш на материал `MG`, `mgBox`, `mgCy`, `mgAdd`, `mgEnd`. Здесь же плоскость разреза `CLIP`. Поля `cc` (лак), `sheen` (ворс ткани) и `tr` (стекло с френелем) делают материал `MeshPhysicalMaterial`.
- `src/app/models.js` каталог моделей `MODELS` с размерами и категориями `CATS`, построители 3D `MB`, названия частей `PARTN`, список частей модели `modelSlots`, условные значки для 2D `sym2D`.
- `src/app/fence.js` заборы. Девять видов `FENCES`, прямой пролёт забора `fenceRun`, створка `gateLeaf`, ворота и калитка `gateAssembly`, забор участка `buildFence` с воротами и калиткой по `S.plot.fence`, настройки забора в панели, значок ворот на плане `fence2D`.
- `src/app/models2.js` вторая часть каталога: машины шести кузовов по таблице `CARS` и общему `carBody`, мотоцикл, велосипед, секция забора, ворота и калитка как объекты, мебель, двор, растения. Сюда же категория «Заборы и ворота».
- `src/app/kitchen.js` конструктор кухни, как Custom Furniture в Homestyler. Виды модулей `KMODS` (тумба, ящики, мойка, плита с духовкой, посудомойка, пеналы с холодильником и духовкой, шкаф-пенал). У кухни в `mods` лежит список `{t, w}` слева направо, если смотреть спереди, ширина кухни равна сумме (`kitFix`), `up: false` убирает верхние шкафы. Без `mods` модули берутся из ширины `kitAuto`, так строятся старые планы. `MB.kitchen` и значок на плане `kitSym` рисуют по модулям, `kitSec` и `kitBind`, `kitAction` дают правку в панели, `kitKeepLeft` держит левый край на месте, `kitBoq` добавляет смету кухни в ведомость.
- `src/app/walls3d.js` функция `wallSolid`, которая собирает все стены в одно тело. Её же зовут постройки на участке.
- `src/app/core.js` данные, общие шаблоны (нейтральный `presetExample` с мебелью и без, пустой участок `presetBlank`), геометрия стен, правки (поворот, удаление, копия, проёмы, прилипание комнат), история, `sanitize`, сохранение, флаг сайта `WEB`.
- `src/app/plan2d.js` 2D-редактор на SVG, зум и сдвиг плана, значки дверей по типу открывания, проёмы построек, компас, свес и конёк крыши на плане участка, выгрузка плана `planSVG`.
- `src/app/panel.js` правая панель (свойства, каталог, проект), настройки крыши, двери и окна, ворота построек, свет ламп `lampSec`, меню, горячие клавиши, всплывающие подсказки кнопок, светлая и тёмная тема `applyTheme`, сворачивание панели `setSide`, `renderAll`.
- `src/app/matui.js` материалы по частям. Части дома `HSLOTS`, списки частей у любого объекта `slotsOf`, окно выбора материала с круговой палитрой, HEX и RGB.
- `src/app/presets.local.js` мои личные шаблоны с настоящими планами. Файл лежит только у меня на диске, он в `.gitignore`, сборка сайта его пропускает, а без него локальная версия стартует с примера. Подключён с атрибутом `data-local`, сборка вставляет такие скрипты, только если файл есть.
- `src/app/wizard.js` мастер нового участка.
- `src/app/furnish.js` «Обставить комнату», аналог AI Decor из Homestyler на правилах. `fnCtx` считает чистый контур комнаты, стороны, зоны прохода перед дверями и окна. `fnWall` ставит модель спиной к стене (`FN_ROT`) в первое подходящее место по списку сторон `fnSides` (сначала без дверей, по желанию без окон, длинные раньше), `fnAt` ставит предмет перед другим, `fnFree` ищет свободное место ближе к центру. Высокое не встаёт под окно, если выше подоконника. Наборы по типу комнаты в `fnPlan`, «Кабинет», «Детская» и кухня-гостиная узнаются по названию. `furnishRoom` заменяет мебель в комнате и пишет историю.
- `src/app/three-d.js` объект `V`, 3D-сцена, свет, сборка дома и участка в `build3D`, разрез, перевод координат.
- `src/app/lamps.js` свет от ламп. Температура света в цвет `kelvinColor`, общий выключатель `LAMP.mode` (`auto`, `on`, `off`), потолочный свет в комнатах `autoLights`, отбор источников по бюджету качества `LAMP_CAP` в `lampsFinish`, ореолы, маски комнат `lampMaskHouse` и `lampSync`, выключатель лампы `toggleLamp`.
- `src/app/openings3d.js` двери, окна, арки и проёмы построек в 3D, анимация открывания `ANIM`, `toggleOpen`.
- `src/app/roof3d.js` крыша. `roofCalc` считает скаты как нижнюю огибающую плоскостей, `roof3D` строит кровлю, подшив, торцы, фронтоны, коньки, водостоки и дымоход.
- `src/app/sky.js` положение солнца по координатам и времени `sunPos`, небо с облаками и звёздами, погода `WEATHER` (в том числе гроза и град), дождь, снег и град частицами с учётом ветра, путь солнца, часы солнца по фасадам и комнатам.
- `src/app/weather.js` симуляция погоды `WX`. Климат по месяцам `airTemp`, накопление снега, мокрого и луж, таяние и высыхание `wxStep` (идёт, пока бежит время), ветер `windVec`, молнии `boltMake` со вспышкой через свет неба, времена года `seasonKey` и цвет газона `grassKey`, окно «Погода и симуляция».
- `src/app/ltpl.js` шаблоны света `LTPL`, как Daylight и Night в Homestyler. Кнопка с лампочкой в ленте времени открывает `#tplpop`, `ltplApply` ставит время дня `ltplTime`, погоду и режим ламп. «Светлый интерьер» держится в `UIP.lt`: `applySky` поднимает экспозицию на 30% и свет неба, `inAmbK` меньше приглушает рассеянный свет внутри дома.
- `src/app/refine.js` докрутка картинки, пока камера стоит. Копит кадры со сдвигом камеры, солнцем внутри его диска и светом неба из случайных сторон, получаются мягкие тени и затенение в углах. Первые `RF.show` кадров копятся скрыто, дальше картинка плавно перетекает из обычного кадра к накопленной до `RF.full`. Обычный кадр `rfGrab` копирует из холста после каждого рисования. Число кадров за такт `RF.k` подстраивается под скорость. Качество `QUALITY`.
- `src/app/sunmap.js` карта солнца на участке `SMAP`. `smapCompute` рисует землю сверху камерой на слое 1 при солнце каждые 15 минут и складывает освещённость в half float, `smapFinish` переводит её в часы, раскрашивает палитрой `SMAP_PAL` и считает долю участка с 6 и 4 часами. Слой 1 получают земля участка и низкие объекты `smapLow`. Оверлей в 3D `smapOverlay`, в 2D `smap2D`, значение под курсором `smapAt`, легенда `smapUI`.
- `src/app/measure.js` рулетка `MEAS`. Точки замера хранятся в координатах мира `{x, y, z}`, поэтому замер из 2D виден в 3D и наоборот. Привязка в 2D `measAt2` к чистым углам комнат (с учётом толщины перегородок), торцам проёмов, углам мебели, построек и участка и к граням стен, в 3D `measAt3` к ближайшему углу на экране. Линия и подпись в 3D `measSync3`, в 2D их рисует `measSVG` из `plan2d.js`.
- `src/app/boq.js` ведомость объёмов для сметы. `boqRows` отдаёт строки `[раздел, название, количество, единица]`: наружные стены и кладка по оси, фасад, цоколь, отмостка, перегородки, полы и стены внутри по материалам (`boqRoom` считает чистые размеры комнаты, вычитает проёмы и места без стены), плинтус, потолки, окна и двери по размерам, кровля по скатам (`boqRoof` берёт площади из `roofCalc`, конёк и рёбра из `roofEdges`, карниз и фронтоны по высоте крыши над стеной), забор, ворота и мощение. Таблица внизу вкладки «Проект» `boqHTML`, выгрузка `boqCSV` в CSV с BOM и точкой с запятой для Excel.
- `src/app/video.js` видео облёта и дня `recordVideo`. Холст временно становится 1280 × 720, `captureStream` и `MediaRecorder` пишут WebM (в Safari MP4). Облёт идёт по кругу вокруг точки из `viewPose("iso")`, день двигает `SKY.t` от рассвета до заката с запасом 40 минут. Кадры считаются по реальному времени, поэтому на слабой видеокарте видео получится дёрганым, но нужной длины. Пока пишется, стоит `V.busy`, цикл 3D не рисует, отмена та же, что у рендера, `HQ.cancel`.
- `src/app/gaps.js` размеры до стен у выбранного, как «2D/3D Positioning» в Homestyler. `gapsOf` даёт расстояния в четыре стороны: у мебели лучом до ближайшей грани стены (`gapFaces`, перегородки с учётом толщины), у построек и дома до границ участка. В 2D их рисует `gapsSVG`, в 3D слой `#gaps3` поверх холста (`gaps3Sync` после каждого кадра, у подвешенной мебели ещё до пола и потолка). Клик по числу открывает поле `#gapin`, Enter сдвигает предмет так, чтобы расстояние стало введённым (`gapApply`).
- `src/app/controls3d.js` камера, управление мышью, тачпадом и клавишами, прогулка, выбор кликом, двойной клик и E открывают двери, манипуляторы `GZ`, установка проёмов и моделей в 3D.
- `src/app/render.js` рендер высокого качества `renderHQ` на той же схеме света, что и докрутка, снимок, ZIP со всеми видами, лист A3, превью каталога. Кнопка «Рендер» открывает окно `#rpop` с размером `RSIZES` и размытием фона `RDOF` (`RND`). Размытие считается тонкой линзой: камера каждого прохода сдвигается по диску диафрагмы, а сдвиг кадра `setViewOffset` держит резкой плоскость фокуса. Фокус в центре кадра или на точке, выбранной кликом (`rpopPick`, `focusPoint` пропускает сетчатые заборы).
- `src/app/pano.js` панорама 360° из текущей точки камеры. `panoRender` считает шесть граней куба через `renderHQ` (поле зрения 90°, ориентация `quat` из `panoFaces`), `panoStitch` склеивает их в равнопромежуточную картинку 2:1, середина кадра смотрит туда же, куда камера. `panoXMP` вписывает в JPEG метку GPano, по ней телефон и VR-просмотрщики узнают панораму. Просмотр `panoOpen` идёт в своём окне `#panov` со вторым WebGL-контекстом, закрытие его освобождает.
- `src/app/main.js` запуск приложения.
- `dist/plan-doma.html` собранный файл для меня, `site/index.html` собранный сайт. Руками не правь, только через сборку, в git они не идут.
- `tools/check.cjs` проверка логики, `tools/render3d.cjs` рендер 3D.

Скрипты классические, без модулей и бандлеров, потому что страница должна открываться через `file://`. Глобальные `const`, `let` и функции из одного файла видны в остальных. На верхнем уровне файла можно обращаться только к тому, что подключено раньше, в функциях можно ко всему.

## Модель данных

Всё состояние лежит в объекте `S` версии 3. Он же уходит в localStorage под ключом `house-plan-v2` и в файл экспорта в виде `{plan: S}`. Настройки интерфейса лежат отдельно под ключом `house-plan-ui`, там же шаблон «Светлый интерьер» (`lt`), тема (`auto`, `light`, `dark`), свёрнута ли панель, день, время, погода, снег, мокрое, лужи и ветер (`wx`), скорость времени, режим света, качество 3D и последние цвета палитры.

- `plot` размеры участка `w`, `d` и отступы `street`, `side`, `back` в метрах. Забор `fence`: вид по бокам и сзади `type`, вдоль улицы `front` (ключи `FENCES`), высота `h`, ворота `gate` (`swing`, `slide`, `none`) шириной `gw` со сдвигом центра от середины улицы `gx`, калитка `wicket` справа или слева `wside` (1 или -1), насколько открыты ворота `go` и калитка `wo`. Без поля берутся значения `fenceDefault`.
- `site` широта `lat`, долгота `lon`, часовой пояс `tz` (часы от UTC), север `north` и город `city`. Север это угол стрелки на север от верха плана по часовой стрелке, 0 значит улица на юге.
- `house` центр дома на участке `cx`, `cy`, поворот `rot` (0, 90, 180 или 270), толщина наружных стен `wall`, перегородок `inner`, высота потолка `h`, цоколь `base`, высота проёмов `doorH`. Крыша `roof` (`gable`, `hip`, `halfhip`, `pyramid`, `gambrel`, `shed`, `flat`), уклон `pitch` и верхний уклон ломаной `pitch2` в градусах, конёк `ridge` (`long` или `short`), низкая сторона односкатной `low` (`f`, `b`, `l`, `r`), доля полувальмы `hipCut`, свес по карнизу `over`, свес по фронтону `overG`, водостоки `gutters`, дымоход `chim` в точке `chx`, `chy` координат дома на высоте `chh` над коньком, потолочный свет в комнатах `autoLights`.
- `rooms` прямоугольники `{id, name, type, x, y, w, d, open}` в координатах дома. Типы и их цветовые группы в `TYPES`.
- `nowall` пары id комнат `[[a, b], ...]`, между которыми стены нет, даже если комнаты не открытые. Поля нет, если пар нет.
- `doors` объекты `{id, x, y, o, w, side, hinge, kind, op, leaf, open}`. Точка `x, y` это центр проёма на линии стены, `o` ориентация стены (`h` или `v`), `side` сторона открывания (+1 или -1 по оси поперёк стены), `hinge` конец с петлями (0 у меньшей координаты), `kind` это `door`, `entry`, `open` или `arch`. `op` способ открывания из `DOOR_OPS`, `leaf` вид полотна из `LEAFS`, `open` насколько открыта от 0 до 1.
- `windows` объекты `{id, x, y, o, w, sill, h, op, n, open, how}`. Окна стоят только на наружных стенах. `op` способ открывания из `WIN_OPS`, `n` число створок (0 значит сколько влезет), `open` от 0 до 1, `how` у поворотно-откидного (`turn` или `tilt`).
- `items` мебель и всё, что стоит в доме, `{id, kind, name, x, y, w, d, h, z, rot}` в координатах дома. У кухни (`kind: "kitchen"`) бывают `mods` и `up`, см. `kitchen.js`.
- У секции забора и ворот (`MODELS[kind].fs`) бывает `fs`, вид забора из `FENCES`. У ворот и калитки (`MODELS[kind].gate`) есть `open` от 0 до 1.
- У ламп (`MODELS[kind].lamp`) бывают поля `on` (false значит выключена), `k` температура света в кельвинах и `lm` яркость в люменах. Без них берутся значения модели.
- `objects` всё, что стоит на участке, в том же формате в координатах участка. У гаража, бани и сарая (`MODELS[kind].ops`) есть `opens`, список ворот, дверей и окон `{id, kind, side, c, w, h, sill, op, open, hinge}`. `side` это стена (`f` спереди, `b`, `l`, `r`), `c` сдвиг центра от середины стены вправо, если смотреть снаружи. Пока `opens` нет, работают проёмы по умолчанию из `OPDEF`.
- У объектов, мебели, комнат, дверей, окон и дома может быть `mats`, свои материалы по частям в виде `{часть: {m, c}}`. `m` ключ материала из `MDEF`, `c` свой цвет `#rrggbb`. У комнаты части `floor` и `wall`, у дома части из `HSLOTS`, у двери `leaf`, `dframe`, `handle`, у окна `wframe`, `glass`, `sill_in`, `sill_out`, у моделей части из `modelSlots`.

У `items` и `objects` поля `w`, `d` это размер самой модели без поворота. Центр лежит в точке `x + w / 2, y + d / 2`, поворот `rot` любой, в градусах по часовой стрелке. `z` это высота над полом. Габарит повёрнутой модели считает `thingBox`. Вид модели берётся из `MODELS[kind]`, неизвестный вид становится `other`.

Планы версии 2 `sanitize` переводит сам. У старых построек с `rot` 90 или 270 он меняет `w` и `d` обратно местами и сохраняет центр. Новые поля старых планов получают значения по умолчанию.

## Координаты

- Единица везде метр. Значения округляются через `r2` до сантиметра, сравнение с допуском через `near` (2 см).
- Участок. Начало в левом верхнем углу, ось y вниз. Улица и красная линия внизу, на `y = plot.d`. Задний отступ сверху.
- Дом. Координаты комнат считаются от левого верхнего угла внутреннего контура. Сторона с наибольшим y смотрит на улицу при `rot = 0`.
- Поворот дома и моделей в 2D это SVG `rotate` вокруг центра, по часовой стрелке при оси y вниз.
- 3D. X равен x участка, Z равен y участка, Y смотрит вверх. Группа дома `V.hg` получает `rotation.y = -rot` в радианах, внутри неё группа `V.hgi` в координатах дома. Модель получает `rotation.y = -rot`. Точки из координат дома в мир и обратно переводят `houseToWorld`, `worldToHouse`, направления `dirToWorld` и `dirToHouse`.
- Модель смотрит лицом в сторону `+z` своей группы. Спинка дивана, изголовье кровати и задняя стенка шкафа стоят на `-z`. Передняя стена постройки тоже на `+z`.
- Солнце. `sunPos` даёт высоту и азимут от севера по часовой стрелке. `sunDirOf` переводит их в направление сцены с учётом `site.north`, при `north = 0` юг смотрит в `+z`, на улицу.
- Крыша считается в своих осях u вдоль конька и v поперёк, `roofXZ` переводит их в оси дома.

## Инварианты

- Изменение, которое должно попасть в историю, заканчивается вызовом `changed()`. Она делает `normalize`, `commit`, `save` и `renderAll`.
- Во время перетаскивания `changed` не вызывается. Там только `render2D`, `updateLive` и `schedule3D`, а `changed` звучит один раз в конце. Если двигается или крутится одна модель, вместо `schedule3D` работает `syncThing3D`, она двигает готовую группу без пересборки сцены.
- `normalize` сдвигает комнаты, двери, окна и мебель так, чтобы контур дома начинался в точке 0,0. Всё, что двигает комнату, двигает и привязанные двери, окна и мебель внутри неё (`attachedTo`, `itemsIn`).
- Стены не хранятся. Их каждый раз считает `wallSegs` по комнатам. Стена есть между двумя разными комнатами и между комнатой и пустотой. Между двумя комнатами с `open: true` и между парой из `S.nowall` стены нет, на плане там пунктир. Пару ставит и снимает `setNoWall`, она же удаляет двери на общей границе. Инструмент «Убрать стену» (`tool.t === "wall"`) ищет пару под курсором через `wallPairAt` и переключает её `toggleWallAt`. Общую границу двух комнат даёт `sharedEdge`, соседей `neighbors`.
- Коробки стен для 3D считает `wallBoxes`. Конец стены удлиняется на полтолщины только там, где в него упирается другая стена, иначе у свободного конца торчал бы огрызок.
- Ширина проёма ограничена общей границей комнат по обе стороны (`openingSpan`), кнопка «На всю стену» растягивает проём на неё.
- Наружные стены идут по габариту всех комнат (`extSides`) и стоят снаружи контура толщиной `wall`.
- В 3D все стены собирает в одно тело `wallSolid`. Она раскладывает куски стен в общую сетку ячеек, вычитает проёмы и строит только внешние грани. Перекрытые стены сливаются, мерцания на стыках нет. Грани делятся на группы материалов фасада, внутренней штукатурки, верха и среза. Если у комнаты есть свой материал стен, `cfg.room` отдаёт её внутренним граням отдельную группу.
- Разрез в 3D срезает стены прямо в `wallSolid`, а всё остальное в доме отсекает плоскость `CLIP[0]`. Поэтому материалы дома берутся через `matHouse`, а на участке через `matPlot`.
- Модель берёт материал через `m(имя, часть)`. Без части частью считается само имя материала. `slotMat` подменяет материал, если у объекта есть `mats` для этой части. Новую деталь модели называй частью из `PARTN` или добавь туда подпись.
- Текстуры нейтральные, почти серые, цвет даёт `c` материала. Поэтому любой материал можно перекрасить. Швы плитки, кирпича и мощения красит `c2` через красный канал карты шероховатости, газон и асфальт перемешивают две выборки текстуры по крупному шуму, чтобы не было видно повтора.
- Дверь или окно стоит на стене, если `onLine` совпадает с отрезком стены. Линию ищет `lineOf`, ближайшую стену к точке `nearestWall`, проём по клику создаёт `openingAt`, геометрию двери считает `doorGeo`.
- Ворота забора участка выбираются в 3D как `{t: "fence", part}`, ворота-объекты как `{t: "obj", id, gate: true}`. Двойной клик по ним идёт через `toggleOpen`.
- Ближняя плоскость камеры растёт с высотой камеры `camNear`, иначе дорога и трава вдали мерцают друг сквозь друга.
- Открывание дверей, окон и ворот анимирует `ANIM`. `build3D` сначала зовёт `animClear`, построители регистрируют повороты через `animBind`, `toggleOpen` меняет `open`, пишет историю и двигает цель анимации без пересборки.
- Комната при перетаскивании, растягивании и рисовании прилипает к краям соседних комнат ближе 25 см (`magnetRoom`). Alt отключает прилипание и сетку.
- Мебель при перетаскивании в 2D и 3D проходит через `snapThing` (`snap.js`): сначала `snapOut` выталкивает её из стен в сторону центра, потом мебель из `SNAP_WALL` ближе 30 см к стене разворачивается к ней спиной и встаёт вплотную, потом края липнут к граням стен (20 см) и к краям соседней мебели (8 см). Поворот считается от поворота в начале перетаскивания, поэтому вдали от стен он возвращается. Мебель с поворотом не кратным 90° не разворачивается. Alt отключает всё это.
- Всё, что приходит из localStorage или файла, проходит через `sanitize`. Новое поле добавляй туда же с дефолтом и ограничением диапазона.
- 3D пересобирается целиком в `build3D`, не чаще раза за кадр, через флаг `V.rebuild`. Геометрии освобождает `clear3D`, материалы кэшируются в `MATC`, текстуры в `TEXS`, подписи в `LABELS`. Материалы со своим цветом, которых больше нет в сцене, чистит `pruneMats`.
- Любое изменение кадра ставит `V.need`, цикл рисует обычный кадр и сбрасывает докрутку `refineReset`. Если 160 мс ничего не менялось, `refineTick` копит кадры до `RF.max`. Дождь и снег двигаются каждый кадр, поэтому при них докрутки нет.
- Свет неба в докрутке (`RF.skyL`) даёт только рассеянный свет. Шейдер узнаёт его по номеру среди направленных источников `SHU.uSkyIdx`, номер считает `dirLightIndex` так же, как three.js сортирует источники. На время докрутки рассеянный свет от карты окружения падает до 35% через `SHU.uEnvDiff`, отражения не меняются, поэтому блики не прыгают.
- Время, дата и погода меняются через `skySet` и `applySky`. Она ставит солнце, цвет неба, экспозицию и туман, пересчитывает карту окружения не чаще раза в 180 мс. Смена месяца кладёт снег по климату `seasonSnow`, смена погоды ставит типичный ветер.
- Снег, мокрые поверхности и лужи рисует общий патч шейдера по юниформам `SHU.uSnow`, `SHU.uWet`, `SHU.uPud`: снег ложится на грани, смотрящие вверх, лужи только на ровных местах ниже 1,2 м, внутри дома ничего этого нет. Сколько воды держит покрытие, задаёт поле `pud` материала. В дождь в лужах расходятся круги.
- Ветер качает листву и кору (материалы группы `plant`) в вершинном шейдере, внутри дома растения не качаются. Пока дует ветер, идут осадки или гроза, кадр рисуется каждый такт, и докрутки нет.
- Деревья, кусты, клумбы и грядки строятся по сезону `WX.season`. Смена сезона пересобирает сцену и сбрасывает превью каталога.
- Клик по блоку в 3D идёт через `hitScene` и `selectPick` и переключает вкладку под тип блока. Повторное перетаскивание уже выбранного блока двигает его. Двойной клик по двери, окну или воротам открывает их, в прогулке то же делают клик и E.
- Активный инструмент лежит в `tool` (`room`, `open` с видом проёма, `wall`, `meas` или `thing` с видом модели), режим манипулятора в `gmode`. Меняются только через `setTool` и `setGmode`.
- Лампы светят `PointLight` с затуханием по квадрату расстояния (патч `bsdfs` в `shade.js`). Каждая лампа светит только в своей комнате или группе открытых комнат, уличные только снаружи дома. Маски лежат в `userData.la` и `userData.lb` источника, `lampSync` раскладывает их в `SHU.uPLA` и `SHU.uPLB` в том же порядке, в каком three.js нумерует источники (сначала с тенью, потом без). Она висит на `V.scene.onBeforeRender` и пересчитывает порядок, только когда меняется `LAMP.ver`.
- Тени ламп не обновляются каждый кадр (`shadow.autoUpdate = false`). После сдвига модели или анимации дверей зови `lampShadowsDirty`.
- Свет от ламп собирается в `build3D`: `lampsBegin`, модели кладут точки света в `P.lights` через `lightAt`, `lampThing` и `autoLights` копят кандидатов, `lampsFinish` создаёт источники. Детали лампы вокруг точки света не должны отбрасывать тень, для этого `ns()`.
- В рендере высокого качества `V.hq` прячет подписи, выделение, красную линию, путь солнца и манипуляторы.
- Карта солнца считается заново через 450 мс после любого изменения участка, дома, построек, забора или даты (`smapSig`). Пока она считается, стоит `V.busy`, и цикл 3D не рисует. Если открыт только 2D, `smapCompute` сама собирает сцену через `build3D`.

## Подводные камни

- three.js r128 старый, но новые версии идут без глобальной сборки и через `file://` без модулей не заработают. Не обновляй без моего согласия.
- В r128 у `Texture` нет `userData`, у `THREE.Color` нет `addScaledVector`. Тонмаппинг в r128 работает и при рисовании в render target, туман подмешивается уже после тонмаппинга, поэтому его цвет задаётся в sRGB.
- Две глобальные функции с одним именем в разных файлах не дают ошибки, работает та, что подключена позже. Так старая `buildFence` из `three-d.js` тихо перекрывала новую из `fence.js`. Перед новой функцией ищи имя по всем файлам.
- Не называй глобальные функции именами встроенных объектов браузера. Функция `Blob` уже перекрывала `window.Blob`, и ломались все скачивания.
- `stroke-width` и пунктир в SVG считаются в метрах через масштаб `k`, поэтому `vector-effect` не используется.
- Во время перетаскивания рамка вида из `baseBounds` заморожена в `frozen`, иначе план прыгает под курсором. Зум и сдвиг плана лежат отдельно в `V2`.
- Клавиша M включает рулетку. Первый Esc сбрасывает замер, второй выключает рулетку, смена инструмента тоже стирает замер.
- Клавиши R, F, M, 1, 2, 3, стрелки и Delete не работают, пока фокус в поле ввода или включена прогулка. W A S D Q E летают только когда курсор над 3D.
- Колесо мыши приближает, два пальца тачпада крутят вид. Отличает их `wheelKind`, если она ошибается, в настройках (шестерёнка) есть переключатель «Прокрутка». Там же выбор, что делают два пальца (`UIP.pad2`: вращают или двигают, Shift меняет на другое), и чувствительность `UIP.padk`.
- Жесты тачпада и колесо мыши не двигают камеру сразу, а копятся в `PADQ`, и `padTick` отрабатывает их плавно каждый кадр. Точку вращения на весь жест выбирает `padPivot`: выбранный предмет, иначе то, что в центре экрана, иначе точка перед камерой. Приближение идёт к точке под курсором `dollyTo`. Любое нажатие мыши и перелёт камеры сбрасывают очередь `padReset`.
- «Вид из окна» (`windowView`) включает прогулку и ставит камеру в комнату перед окном на высоте глаз, лицом наружу. Если створок чётное число, камера сдвинута к середине створки, чтобы импост не делил вид пополам. Esc возвращает прежний вид, как после обычной прогулки.
- Экранный навигатор `#nav3` крутит и приближает вид, пока кнопку держат (`NAV`). Стрелки на клавиатуре крутят вид, когда курсор над 3D и ничего не выбрано.
- Цвета материалов задаются в sRGB и переводятся в линейные через `lin`. Рендер идёт с тонмаппингом ACES и выводом в sRGB. Экспозицию ставит `applySky`, днём 0,72, ночью она сама поднимается.
- SVG плана `#cv` отодвинут от верхней панели и инструментов через CSS (`top`, `left`), чтобы план при вписывании не прятался под плавающими панелями. Если меняешь размеры панелей, поправь и эти отступы.
- Подписи в 3D, `planSVG` и превью каталога не зависят от темы, `planSVG` подставляет светлую палитру `LIGHT`.
- Атрибут `hidden` скрывает элемент через общее правило `[hidden] { display: none !important; }`, без него `display: grid` у рядов перебивал `hidden`.
- Во встроенном браузере скриншот иногда показывает старый кадр, если отрисовку вызвать вручную из консоли. Для проверки выставляй `V.need = true` и жди кадр цикла. Картинку после докрутки удобно снимать через `refineStep(0)` и сразу `toDataURL`, в том же вызове.
- Материал в обход `mat()` не получит `shadePatch`, и в докрутке на нём появятся блики от света неба. Новые материалы заводи через `MDEF` или ключ `вид#цвет`.
- В r128 свет и тени проверяют слои той камеры, которой рисуют. Источник света не с её слоя не светит, а тень отбрасывают только объекты с её слоя. Поэтому карта солнца сначала обновляет карту теней отдельным рисованием камерой слоя 0 (`shadowMap.needsUpdate`), а потом рисует землю камерой слоя 1 без обновления теней.
- Карта теней в r128 не учитывает `alphaTest` материала. Сетчатые материалы с альфой (`fence`, `chain`) отбрасывали сплошную тень. Теперь `alphaShadows` в конце `build3D` даёт таким мешам `customDepthMaterial` и `customDistanceMaterial` с той же текстурой.
- Холст WebGL создан без альфы, поэтому `rfGrab` копирует кадр в RGB-текстуру. С RGBA `copyTexImage2D` падает с INVALID_OPERATION.
- Смена числа источников света перекомпилирует все шейдеры. Поэтому днём при режиме «Свет сам» ламп в сцене нет совсем, а включение в сумерках даёт одну заметную паузу.
- Мышь и тачпад вживую человеком ещё не проверены, только jsdom и встроенный браузер. Перед крупной правкой взаимодействия попроси меня прокликать чеклист из `docs/testing.md`.
